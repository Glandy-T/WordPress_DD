# FORMAT 动画机制与本项目可行性

日期：2026-10-03（日本时间）。来源：[FORMAT 实际网站](https://format.obys.agency/)。本轮仅检查公开网页资产与实际表现，未修改 WordPress，未制作本项目试作。

## 结论

缩小范围和幅度后，图片视差、局部旋转／伸缩、形状之间的连续过渡、文字分批进入等效果可以在开发用 WordPress 中实现。复杂的跨区接力和物理碰撞工作量明显更大。

FORMAT 的手机提示明确写着 “Sorry, this experience is designed for desktop devices.”，所以其桌面实现不能作为本项目手机端已经可用的证据。手机布局、触发范围和可读性必须单独设计。

## 查验方式与证据范围

- 读取页面 HTML、公开主脚本 `/assets/index-CzAHO6hM.js` 和样式 `/assets/index-D1Q7NR-y.css`。
- 用 Chromium 查看1440×1000桌面页面，分段滚动并记录元素 transform 与 clip-path；在多个滚动位置观察到中心图形 polygon 点位改变、海报缩小为卡片。
- 用390×844窗口查看手机提示；样式也明确在 `width <= 767px` 或 `pointer: coarse` 时显示提示层并隐藏页面滚动。
- 检查了公开可见资产，未获取源码仓库，未对全部功能做性能审计。下面的版本与实现是本次访问时观察结果，不保证网站以后不变。

## 已确认的技术组成

| 技术 | 在此站的用途 | 本项目是否必须使用 |
| --- | --- | --- |
| HTML / CSS / SVG | 内容、几何图形、遮罩、裁切、绝对定位与变换 | 基础；按局部需要选用 |
| GSAP 3.15.0 与 ScrollTrigger | 动画时间轴、滚动映射、状态过渡、进入触发 | 复杂组合可用；简单变化可以只用 CSS |
| Lenis 1.3.26 | 平滑滚动，与 GSAP 更新循环同步 | 可省略；不是形变成立的前提 |
| Matter.js 0.20.0 | 卡片掉落、碰撞、点击产生物体 | 普通入口／图片展示不需要 |
| Canvas 2D | 图片像素化过渡、测量字形实际边界 | 对本项目多数基础效果可省略 |

本次 HTML 未发现 video 标签，主脚本未发现 WebGL / Three.js 调用。已分析的核心效果属于实时二维 DOM / CSS / SVG 处理，不能按“整页预渲染视频”理解。

## 1. 滚动位移、旋转、伸缩与图片视差

**机制**：部分动画使用 ScrollTrigger 的 `scrub` 将滚动区间映射到进度。另一些直接计算 `scrollY`、视口尺寸和元素坐标，逐帧修改 translate、rotate、scale 或 CSS 变量。图片预留额外裁切面积，在固定窗口内沿纵向移动，形成视差。

**可行性**：低至中等。只在一个图片区或入口内做小幅位移／缩放，不需要物理引擎。字体正文应保留独立布局，不能跟着整个画布缩成小字。

**限制**：移动过大时图片会露出空边；要预留裁切面积。图片加载与布局变化会改变触发位置，需要重新测量。手机滚动体验不能依赖桌面鼠标滚轮和平滑滚动参数。

## 2. 形状之间的连续变化

**确认的代码机制**：

1. 为 Vertical、Horizontal、Circle、Triangle、Complex 等状态定义轮廓。
2. 按轮廓周长把每种形状重新采样成72个点，确保两个状态有相同点数。
3. 逐点计算中间位置：`当前点 = 起点 + (终点 - 起点) × 进度`。
4. 拼成 CSS `clip-path: polygon(...)`，裁切两个图形面板。
5. 当选中状态变化时，用 GSAP 做约0.55秒的 `power2.inOut` 过渡。
6. 如果在过渡中又换状态，先读取当前中间轮廓，再从这里转向新目标，避免突然跳回原形。

**一个关键区别**：形状状态由滚动位置选择，但选定后执行短时间过渡；并非页面上所有效果都严格随滚动速度逐帧前进。不能把“滚动映射”和“滚动触发后播放”混为一谈。

**可行性**：中等。少量几何模块可以使用更少的点或 SVG，未必要保留72点。矩形伸长、斜角变化等简单形变通常更容易。

**限制**：点数相同还不够，起始点、绕行方向和对应位置也须合理，否则中间形状会扭曲或自交。多个大面积裁切同时变化的手机成本需实测。不要把正文放进会把它裁掉的形变区域。

## 3. 同一元素跨区域接力

海报在前一段是大尺寸内容，后续逐步缩小成卡片，转入物理区域。代码同时管理中心位置、缩放、旋转、滚动测量与物理对象交接。不是只给区块加一个“进入动画”。

**可行性**：中高。缩小幅度能改善观感，但布局变化、窗口重测、反向滚动和状态交接的复杂性仍存在。若只是借鉴局部变化，可以避免跨区接力；是否采用由用户决定。

## 4. 掉落与碰撞

代码创建 Matter.js 世界、矩形刚体、边界和重力，随后将物体坐标写回 DOM transform。点击物理区域可产生物体；滚动速度也参与重力变化。海报进入这一世界时会从动画控制切到物理控制。

**可行性**：高成本，尤其包含反向滚动与手机时。普通年次入口没有必要依赖这种效果。减少运动幅度不能自动消除物理状态管理的工作量。

## 5. 图像与文字的辅助效果

- 文字分批进入：部分标题逐字拆成 span；页脚使用时间轴与 stagger 分批移动，属于常规动画。
- 像素化：Canvas 把图片先画成低分辨率，再逐步提高分辨率，关闭图像平滑；不是把静态图片替换成一段视频。
- 时钟与旋转：有基于当前时间的真实时钟，也有在可见区内播放、离开后暂停的持续旋转。

**可行性**：文字分批出现较低，像素化为中等。日文逐字效果需要额外考虑换行、字符组合与读屏；图片最终必须能恢复到清晰的静态内容。

## 手机与 WordPress

原站大部分空间关系以1440宽基准计算：`--s = innerWidth / 1440`，再乘固定坐标与尺寸。手机提示层下，部分正文实际计算字号只有约2.17px；这不是可移植的手机排版方案。

本项目应使用自己的响应式内容结构，保留日文正文的可读字号，再给指定局部增加动画。桌面 hover、手机滚动触发和减少动态效果下的静态状态要分别处理。不能通过删除 FORMAT 的手机提示层就宣称完成手机适配。

开发站可以加载独立 CSS / JavaScript 与所需库，实现这些二维效果。学校站仍需确认可用的自定义样式、脚本或插件入口；WordPress 正文复制不会自动带入动画脚本。若学校只有受限制的正文编辑功能，部署能力会成为实际限制。

## 建议用于后续选择的范围

| 效果 | 开发站判断 | 验证重点 |
| --- | --- | --- |
| 图片轻微视差、局部移位／旋转 | 可实现，低至中等 | 裁切、手机滚动与阅读 |
| 少量模块伸缩与形状变化 | 可实现，中等 | 默认／激活构图、轮廓对应关系 |
| 滚动选状态后平滑切换 | 可实现，中等 | 连续切换、反向滚动、焦点规则 |
| 一个元素跨多个区块接力 | 可实现，中高 | 状态交接、尺寸变化、内容编辑后的位置 |
| 物理掉落、碰撞与滚动重力 | 可实现但成本高 | 性能、触屏、恢复与维护 |

目前没有选定采用哪一段，也没有把建议变成页面变动。用户认可的是动画参考价值，实际制作应先确定具体效果和目标区域，再做范围明确的验证。
